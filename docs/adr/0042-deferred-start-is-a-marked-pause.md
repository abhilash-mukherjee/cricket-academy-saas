# A later start is a deferred start, not a future valid-from

ADR-0035 stores valid-from as today or earlier so a new Enrollment is Active, and rejects a future start because a term that has not started would need a fourth status. An Owner still needs a Player recorded today to begin on a later day. Accept and manual add take that start on the Asia/Kolkata calendar. Today or earlier is valid-from and creates no pause. A term that is already over stays rejected. A start after today keeps valid-from as today and, in the same transaction, writes a dated pause whose last day is the day before that start. The pause row is marked `is_deferred`. Only those two creates set the mark. The Pause action cannot, and Resume does not clear it. There is no fourth status and no cap on how far ahead. While that pause is open the Enrollment is paused and the Owner sees Starts later, the first day the Player attends, and a valid-until counted from that start rather than the shorter date stored until the pause ends. Resume before that start shortens the end to the days actually paused. The Player stays off the directory's paused cut and is not Lapsed. A Session list, and a blocked second Enrollment on that pair, say the Player starts later. The mark is there so a later limit on ordinary pause length can ignore these days. That limit is not part of this decision. Age and Guardian stay as of today (ADR-0034). The conversion page does not collect the start.

**Considered options:** A future valid-from and a fourth status (rejected — ADR-0035; roster, directory, and pause would each grow a new state); a future valid-from left Active because valid-until is still ahead (rejected — the Player would read as Active before attending, and nothing would record that the days were a delayed start); an ordinary pause with no mark (rejected — the same dates can be a real absence, and a later pause-length limit could not tell them apart); a pause-type enum that also names ordinary pauses (rejected — an ordinary pause is just a Pause); enforcing a maximum ordinary pause now (rejected — the use case is only the delayed start).
