# UI is mobile-first on every chrome

Brochure, conversion page, product homepage, auth, Owner/Coach ops, and Super-admin console are designed for a phone first; wider screens add density, not a different product. Guardians register from search on a phone; Coaches mark Session attendance at the ground. A desktop-first `/app/…` would make those jobs second-class and is the default we are refusing. Breakpoints and which Daisy layout a given screen uses stay in specs; the constraint is that a screen that only works with a wide table is unfinished.
